# Automation Anywhere Selectors Guide — recorder formats and property translation

Companion to [source-guide.md § UI Target Locators](source-guide.md): how a recorder capture stores a control's recognition data and which UiPath attribute each recorded property becomes. UiPath vocabulary, reliability tiers, criteria mapping, caption paths (`<nav>`), node identity and confidence tiers: the uipath-genome skill's selector translation — read it first. Observations come from production exports of bots migrated from Enterprise 11 and of native bots: a Java desktop application (Oracle Forms delivered as a Java Web Start applet or a desktop Java client — the worked example of the `JAVA` technology below), its browser launch page in Internet Explorer and Microsoft Edge, Microsoft 365 and corporate identity-provider sign-in pages, Outlook on the web, an Edge PDF viewer tab, Java runtime and Windows credential dialogs. Work from the normalized `a360-targets.json` the source guide's `targets` command derives, never from the base64 blob. Read § Capture format, § Format-wide conventions and § Pitfalls in full; the per-technology tables are a catalog — read the sections for the `technology` values the catalog contains.

## Capture format

One `Recorder.capture` node = one control. Its `uiObject` attribute carries:

| Field | Content | Use |
|---|---|---|
| `uiObject.technologyType` | `JAVA`, `HTML`, `MS_ACTIVE_ACCESSIBILITY`, `MS_UI_AUTOMATION`, `SAP`, `AISENSE` | Decides the UiPath tag chain (§ Technology → chain) |
| `uiObject.controlType` | `TEXTBOX`, `PASSWORD_TEXT`, `BUTTON`, `LABEL`, `CLIENT`, `TREE`, `COMBOBOX`, `LISTVIEW`, `RADIO`, `CHECKBOX`, `MENUBAR` | Decides the acting tag / role and the activity (the skill's rule that one tag is one node); the action attribute is named after it (`textboxAction`, `treeAction`, `listviewAction`, `comboboxAction`, `radioAction`, `checkboxAction`, `menuAction`) |
| `uiObject.criteria` | map `property → {enabled, value}` — the control's **full attribute sheet**, not a chosen short list: a Java capture carries some 16–40 entries, an HTML capture 20–45, an MSAA or UIA capture 16–30, a SAP capture 30–50, of which a few are `enabled: true` (SAP: exactly `Role` and `Object Id`). Only the enabled entries were used for matching; the disabled majority holds pixel geometry (`Left`, `Top`, `Width`, `Height`), `States`, `Index`, `Path` and every name the recorder read — for SAP the technical field name, caption and tooltip. A value may be a variable expression (`$intStatusIndex$`, `$strMenuItemName$`) or a path with a variable tail (`1\|1\|2\|…\|$vRowIndex$`). The blob's `Criterias` property is a names-only list, absent on most captures — never the source of criteria; a SAP capture's blob holds only the capture point and the recorder version — no object node, no path, no name. A capture with **no** enabled criterion is an anomaly to report, not a reason to reach into the disabled ones | The recorded match set — the left side of the tables below. Folding in "everything the capture knows" does not narrow the match, it pins the control to a screen position on the capture machine |
| `uiObject.blob` (base64 JSON) → `objNode` | the object as captured: `name`, numeric `role`, `description`, `className`, `id`, `value`, `windowTitle`, `path.objPath[].index` (accessibility tree path), bounds and click point, `technology.techType` / `platformType`, `attributes[]` (every property the recorder read, enabled or not) | Disabled properties still carry information (an accessible name the author did not match on); the `path` is the positional identity |
| `uiObjectWindow.expression` | `$window-N$` → a WINDOW variable of the bot: `window.name` (title with `*`), `window.class`, `window.path` (executable) | The window tag (`<wnd>` / `<html>`) |
| action attribute + `value` / `valueCV` | what was done (§ source guide, Signals) | The activity and, for a SETTEXT with tokens, the composite pattern |
| `screenshotMetadataPath` / `thumbnailMetadataPath` | PNG names under `<Bot>Metadata/` | A picture of the control and its screen at capture time — the executor's aid when deriving a target offline |
| `blob.browserFramework`, `blob.captureVersion` | present on captures made with the source platform's recorder (`captureVersion` is the recorder's build number; SAP captures carry their own series); absent on captures converted from Enterprise 11 | Which recorder produced the properties; v11 conversions carry `uniqueID` / `class` keys, native captures `uniqueId` / `className` |

The same control recorded twice (a live capture and its disabled twin, or the same field in several bots) differs in `Path` (`-1|1|2|…` vs `1|1|2|…`), sometimes in the enabled criteria set, never in `Name` / `Role`: collapse on window + `Name` + `Role` (+ `Index` when it is a literal).

### Format-wide conventions

- Only **enabled** criteria were matched at run time. The disabled properties in `objNode.attributes` are context that supplies the semantic description (the class of a button, geometry, `States`), with one exception: a disabled `Name` identifies a control that the enabled criteria locate by position (`Path` / `Index` below, pitfall 1).
- Criteria values are exact matches with `*` wildcards allowed (window titles use them; control names rarely). A variable expression as a value (`Name="$strMenuItemName$"`, `Index="$intStatusIndex$"`) becomes a selector variable `{{Argument}}` bound to the workflow argument.
- `Path` is the accessibility tree path from the window, one child position per level, separated by `|`: `k` is the parent's k-th child, `-k` its k-th child counted from the end (`-1` the last). The vendor documentation calls `Path` the control's numeric position in the application and says no more (vendor documentation); the negative reading is confirmed on a live Windows file dialog, whose `File name:` path `4|1|4|1|4|-1|-2|2|4|1|4` resolves to the field only when `-1` and `-2` count from the end. Where a path starts differs by technology. A Java path's first segment (`-1` or `1`) is the window itself and is dropped *[Inferred]*. An MSAA or UI Automation path starts at the window's own children; an MSAA window object has seven standard children with the client area 4th, so an MSAA path alternates `4` with a child position at every child window. An HTML path counts element children from `body`, in the frame's document for a capture in a frame, and its last segment can end one level below or above the element that `HTML Tag` and `DOMXPath` name (a link's inner text, a table's first cell) *[Inferred]*: where a capture also records an absolute `DOMXPath`, the two agree step for step above that end. `Index` is the control's child position under its parent — the last segment of the recorded `Path`, not a count across the window. Both are **position** (the skill's rule that position is strict and last), never an attribute. The path replay is the last resort, just above leaving the control without a selector (the skill's rule that position is strict and last and its rule that no selector is a valid outcome): a capture from which any selector can be built — from a `Name` (enabled or disabled), an id, an automation id, a caption recorded beside the control, or attributes with an `idx`, flagged — takes that selector, and its path stays in the description. Only when none can be built does a literal path replay with `<nav>`. An MSAA path counts the children a snapshot of the window shows, so each of its segments is one `child` step from the window (§ Active Accessibility, `Path` row); a Java or UI Automation path counts the window's children in that technology's tree, which the replay enters with the technology's empty tag (the `Path` rows of § Java and § UI Automation); an HTML path is one `css-selector` (§ HTML, `Path` row). A UiPath `idx` counts matches of the node's attributes under its parent node, so an `Index` copied onto a bare element under the window points at another control or at none: use the capture's `Name` when it has one; otherwise scope the element under its parent (§ Java, `Parent` row) and let the live capture set the index relative to that parent.
- `States` (`enabled,focusable,visible,showing,editable,single line`) is state — never in a target. As an **enabled criterion** (`States="enabled,focusable,visible,showing,active,modal,resizable"` on a `Client`) it means "the modal dialog currently showing": the target is the dialog (`role='dialog'` / the popup's frame), the state is what the driver checks at run time. As the **property a GETPROPERTY reads**, it is an enabled check (contains `enabled`) → Get Attribute `enabled` or Check App State on the button, never a selector attribute.
- `Top` (a y-coordinate in pixels) is position, like `Path`; it appears beside a `Path` when two same-named fields sit in one column.
- Numeric `objNode.role`: 1 = push button, 5 = text, 66 = static text / label, 0 = client area, 25 = HTML client (`DIV`); the string `Role` criterion (`PushButton`, `TextBox`, `StaticText`, `Client`) is the readable form.
- No capture records the executable of the browser or the URL of the page; `url` comes from the `openbrowser` / `runApp` command that opened the page or from the `HTML FrameSrc` host, `app` from the WINDOW variable's executable.
- A WINDOW descriptor may carry `nameCaseInsensitive: true` (the title was matched without regard to case) and, on a keystroke command, a `presetType` naming a special target instead of a window (`TASKBAR`; `CURRENTLY_ACTIVE` = whatever has focus). Both are source facts the catalog carries into the target's description; whether the target's matcher has a counterpart is decided at build, and a title matched case-insensitively in the source is a title to verify live before it is written case-sensitively.
- Passwords typed by a `PASSWORD_TEXT` capture are CREDENTIAL references or redacted literals; the target is the field, the value is the credential asset.

## Java (Java Access Bridge) → `wnd` + `java`

Criteria observed: `Name`, `Role`, `Path`, `Index`, `Top`, `States`, `Description`, `Parent`, `Class`. The criteria set and the `Role` → `role` mapping are the recorder's and hold for any Java application; the Notes column was observed on an Oracle Forms applet and is a worked example — read another application's captions, shortcuts and toolbar from its captures. **Native captures are position-first**: the source platform's recorder enables `Path` (and `Top`) by default and `Name` only when the author ticked it, so `Path` is the most frequently enabled Java criterion and a large share of native controls has no name at all (pitfall 11); grids are walked by a `Path` tail with a per-column base offset, and `Index` as a row counter is the migrated-bot form. The rows below are ordered accordingly: the identity rows first, then the positional forms a native export leans on.

| Criterion | UiPath | Confidence | Notes |
|---|---|---|---|
| `Role` `TextBox` | `<java role='text' />`; the acting activity is Type Into / Get Text | — | Text items and grid cells are both `text`; `GETPROPERTY Sentence` reads a multi-line field's text |
| `controlType PASSWORD_TEXT` (`passwordtextAction SETTEXT`) | `<java role='password text' name='<Name>' />`; Type Into with secure text | high with `Name` | A password field is its own role, never `text`: a `text` selector does not match it |
| `Role` `TreeView` (`controlType TREE`, `treeAction GETTOTALITEMS`) | `<java role='tree' />` for the count; the rows are `<java role='label' />` (or `text`) nodes under it, one per visible line | medium | A menu tree whose captions carry a level prefix (`Level 1 <menu>`, `Level 2 <sub-menu>`, `Level 0 <screen>` in Oracle Forms); the bots walk rows by `Index` + `Path` tail — the UiPath target is the tree item by caption (menu path pattern), level prefix removed |
| `Parent` = `Level 1 <menu>` on a `Level 2*` row | the tree item's parent node (`<java role='label' name='Level 1 <menu>' />` ancestor) | medium | Scopes a level-2 caption to its expanded parent |
| `controlType COMBOBOX` (`comboboxAction GETPROPERTY Value` / `SELECTITEMBYTEXT`) | `<java role='combo box' />`; Get Text / Select Item | medium (positional when only `Path`) | Poplists (a form's mode selector, a grid's `Type` column) |
| `controlType LISTVIEW` (`GETTOTALITEMS`, `GETPROPERTY ItemCollection`, `SELECTITEMBYINDEX`) | `<java role='list' />`; items `<java role='list item' />` picked by text | medium | The `Find` dialog's result list; `ItemCollection` returns the items joined by `<sep>` — translate the pick as "the item that contains {value}", never the index |
| `controlType RADIO` (`radioAction LEFTCLICK` / `SELECT`) | `<java role='radio button' name='<Name>' />`; Click / Select | high with `Name` | `Domestic`, `Replace existing rows` |
| `controlType CHECKBOX` (`checkboxAction CHECK` / `UNCHECK` / `LEFTCLICK`) | `<java role='check box' name='<Name>' />`; Check / Uncheck | medium (grid check boxes carry `Name=" "` — positional) | `Select/Deselect All`, `Print`, per-row selection boxes |
| `controlType MENUBAR` (`menuAction LEFTCLICK`) followed by `Keystrokes` `v` or `[ALT DOWN]wv[ALT UP]` | `<java role='menu bar' />` then the menu item by name (`View` → …), or the accelerator sent to the frame | low | The bots open a menu and press a letter: name the menu function, keep the accelerator as fallback |
| `Role` `PushButton` | `<java role='push button' />` | — | Oracle Forms buttons carry their caption plus the mnemonic in the name (`OK ALT O`, `Search alt S`, `Connect As alt C`, `No ALT N`, `Yes ALT Y`) — keep the full recorded name, wildcard the mnemonic (`name='OK*'`) only when the caption alone is unique |
| `Role` `StaticText` | `<java role='label' />`, pinned by a `name` pattern | — | Status bar messages and menu-tree captions. A bare `<java role='label' />` returns the first label in the window (a frame caption), so the status-bar line is `name='FRM*'` in Oracle Forms — the message class prefix of the application, wildcarded |
| `Role` `Client` | `<java role='internal frame' />` — the screen or alert frame whose `name` is the recorded `Name` | medium | The screen canvas or an alert; its accessible `Name` is the screen title or the alert text (`Error <code>: Query caused no records to be retrieved.`). Confirmed on an Oracle Forms application: the Java driver exposes a screen and an alert as an `internal frame` whose `name` carries the title or the message, so the read is the frame's `name`; an alert frame holds an `option pane` and its buttons. A read on `role='panel'` returns a canvas without that text. The active screen is the `internal frame` whose state is active (`javastate`), for a title read that names no screen |
| `Name` (literal) | `name` | medium (high when the name is a unique field label) | Field labels end in a colon (`Order No: Required`, `Supplier:`, `Username:`, `Dept : `) — keep the spelling including trailing spaces and colon |
| `Name` = variable expression | `name='{{Argument}}'` | medium | Menu nodes clicked by caption (`$strMenuItemName$`) |
| `Description` | none; semantic description text | — | Same as `Name` on Forms controls |
| `Parent` (`Change Department`, `User Login`, `Menu Search`) | ancestor `<java role='internal frame' name='<Parent>' />` (or `role='dialog'`) | medium | The enclosing Forms window; the one attribute that scopes a repeated alert text to its dialog. An enabled `Parent` is part of the target and is never dropped: every positional or generic element (`idx`, a bare `label`, a toolbar button) sits under that frame node, and its index counts inside it. A capture without `Parent` gets the same frame from the screen its bot navigated to (the title the bot checks), flagged *[Inferred]* |
| `Class` | `cls` | medium | Rare on Oracle Forms (Swing class names like `JButton`) |
| `Path` with a variable tail (`1\|1\|2\|…\|1\|1\|$vRowIndex.Number:toString$`, `$vColumnPath$$vColumnIndex$`), incremented per row from a column base (`<base> + row`, one base per column) — **the native grid form** | the **row rule** of a table pattern (the skill's composite-interaction patterns): the column is the base offset, the row the counter — one table pattern per grid with the columns named by their `Name` (`Status Required`, `Code Required`) or by the log line beside a nameless one (`Amount`) | low | Native bots prefer the path tail to `Index`; the total comes from the `Record: n/m` indicator, not from the grid |
| `Index` = variable (`$intStatusIndex$`) with a `Name` shared by every row (`Status`) — the migrated-bot grid form, and the menu-tree walk in native bots | the same **row rule**: row pinned by the key column's value, cell by the column name; `idx='{{Row}}'` only as the flagged fallback | low | A grid exposes each visible row's cell as a same-named `text`; the recorder counted them top to bottom |
| `Path` (literal, the only enabled criterion) | the disabled `Name` in the sheet, when there is one, is the `name` (pitfall 1); otherwise, when no selector can be built (§ Format-wide conventions), the path replayed under the window (the skill's rule that position is strict and last): the first segment (`-1` or `1`, the window) dropped, the second an empty `<java />` (the window's first Java child) followed by `<nav next='<k-1>' />` when `k` is above 1, and each later segment `<nav child='k' />` — `-1\|1\|2\|2\|2\|1` → `<java /><nav child='2' /><nav child='2' /><nav child='2' /><nav child='1' />`; a negative second segment, none | low; the `Name` row's when named | Positional, flagged, and the description quotes the path. Two captures of one control disagree only on the first segment, the window either way. A variable segment is the row rule of the row above |
| `Index` literal (`Index="30"`, `"77"`, `"82"`) | the disabled `Name` in the sheet, when there is one, is the `name` (a field recorded by `Index` often has a unique label: `Dept : `); otherwise `idx` on a strict selector, a literal, **flagged** (the skill's rule that position is strict and last), and the capture's `Path` replayed (row above) only when no selector can be built; the element sits under its parent node (the screen's `internal frame`, a toolbar's `<java cls='ToolBar' role='tool bar' />`), never directly under the window | low; the `Name` row's when named | Toolbar buttons and unlabeled fields have no name — the log line beside the capture names the function; live capture must find a real identity or the target stays positional. The recorded value is a child position (§ Format-wide conventions) and does not carry over as the UiPath index: a toolbar button's live index counts inside the toolbar node, and a grid row's counts the same-named cells of that frame from 1 |
| `Top` (`536`, `555`, `623`, `642`) | none | — | Pixel row of the field; distinguishes fields stacked in one column of a form section — describe the field by its label, verify live |
| `States` | none | — | state (see § Format-wide conventions for the two uses) |

Component → activity, so substep wording and build agree: `TextBox` → Type Into (with the confirm key when the source typed `[TAB]`; `APPENDTEXT "[TAB]"` is a Tab sent to the field) / Get Text (`GETPROPERTY Value`); `PushButton` → Click, `GETPROPERTY States` → Get Attribute `enabled`; `StaticText` → Get Text, or the caption a `<nav>` path to its field starts from (`Record: n/m` → Get Text and parse the total); `Client` → Get Attribute `name` of the alert / screen frame, or Check App State on the frame when the read only decides a branch; `TreeView` rows → the menu path pattern; `List` → Select Item by text; poplist → Select Item; check box → Check; radio → Select; `Keystrokes` `F5` / `F11` / `Ctrl+F11` / `Ctrl+S` / `F4` → Keyboard Shortcuts targeted at the application frame (the shortcut is the application's function); `[ALT DOWN]<letter>[ALT UP]` after a failed button click → the button's Click with the accelerator as fallback (`Addresses alt d`, `Original Invoice alt O`); `Security Warning` `Alt+I` / `Alt+R` → Click on the dialog's `Run` button (`<java role='push button' name='Run' />` under the `SunAwtDialog`) with the shortcut as fallback. An Oracle Forms **toolbar** is one row of nameless `PushButton`s under one path prefix (`1|1|2|2|2|<n>`; a second toolbar under another); a dispatcher bot maps each function (close, execute query, clear, first / last / previous / next record, save, print, cut / copy / paste) to one index — one Object Repository element per function, positional until the live driver shows a tooltip or description to match on.

**Oracle Forms item names.** The Forms Java client names each item's component after its block and item plus its row counted from 0 (`<BLOCK>_<ITEM>_0` in a single-row block, `<BLOCK>_<ITEM>_<n>` down a multi-row one), and a field that also has an accessible name reports that component name as `virtualname` (the skill's `java` tag). No capture records it: the live attribute listing supplies it. It identifies a field without its label and a grid cell without an index — the item is the column, and the row is a selector variable bound to the 0-based row (`{row - 1}` from a 1-based counter), in place of the `Path` tail and `Index` counter of the grid rows above; whether the row counts records or displayed rows once a block scrolls is unconfirmed *[Inferred]*. A field with no accessible name reports its prompt label as `virtualname` instead; the label repeats, so position stays for that field.

## HTML (Internet Explorer and Edge pages) → `html` + `webctrl`

Criteria observed: `DOMXPath`, `HTML Tag`, `HTML ID`, `HTML Name`, `HTML Type`, `HTML InnerText`, `HTML HasFrame`, `HTML FrameName`, `HTML FrameSrc`, `HTML FramePath`, `HTML TagIndex`, `innerHTML`, `outerHTML`, `Path`.

| Criterion | UiPath | Confidence | Notes |
|---|---|---|---|
| `HTML Tag` | `tag` | — | `INPUT`, `BUTTON`, `DIV`, `B`; a `LABEL` / `CLIENT` control type recorded on a `B` or `DIV` is the text leaf the author clicked — the acting node is the enclosing button or link when one exists (the skill's rule that one tag is one node) |
| `HTML ID` | `id` | high when stable (`username`, `password`, `i0116`, `idSIButton9`), dropped when hash-like | Microsoft sign-in ids (`i0116`, `idSIButton9`) are stable across tenants |
| `HTML Name` | `name` | high | `loginfmt`, `pf.username`, `pf.pass` |
| `HTML Type` | `type` | alright | `email`, `text`, `password`, `submit`, `button` |
| `DOMXPath` `//tag[@attr='value']` — the predicate on the **last** step | the element's own attribute (`name`, `id`) | as that attribute | The recorder builds the XPath from the strongest attribute it found — read it as a hint, translate the attribute, never the path. When the same capture also enables `HTML ID` for that value, the two are one fact |
| `DOMXPath` `//a[@id='value']/div[1]` — the predicate on an **earlier** step, a positional step after it | the predicate's attribute names the element's **ancestor**: when that ancestor is the link or button the recorded leaf sits in, the ancestor's own `id` with the tag the XPath step names (`<webctrl id='value' tag='A' />`); otherwise none on the element — the ancestor scopes it (a `parentid`-style scope) and does not identify it | medium | **The id belongs to the step that carries it.** The ancestor form is common — a click recorded on the text leaf inside an identified link or button. That link or button is the acting node (`HTML Tag` row, the skill's rule that one tag is one node), so the id is its own. Any other ancestor only scopes: translating its id as the element's own targets the wrong node, the trailing positional step is dropped like every index, and the element is identified by its `HTML Tag` / `HTML Type` inside that scope, or is text-pinned |
| `DOMXPath` `…/div[text()='Use another account']`; `HTML InnerText` | `aaname` or `visibleinnertext` of the text leaf (the skill's three-case `aaname` test) | medium | Text-pinned leaf; an `HTML InnerText` that is a variable expression is a selector variable (§ Format-wide conventions) |
| `DOMXPath` positional (`//div[@id='lightbox']/div[3]/div[1]/…/input[1]`) | the `HTML ID` / `HTML Name` / `HTML Type` the same capture records, when they identify the element; otherwise the path as one `css-selector` (the skill's rule that a positional web path is one `css-selector`), its leading `@id` step `tag#<id>` — `css-selector='div#lightbox>div:nth-of-type(3)>div:nth-of-type(1)>…>input:nth-of-type(1)'` | low | Position, flagged (§ Format-wide conventions); the leading `@id` is the ancestor scope of the row above |
| `HTML HasFrame` = `True`, `HTML FrameName`, `HTML FrameSrc`, `HTML FramePath` (`IFRAME[1]/FRAME[1]`) | one `<webctrl tag='IFRAME' name='<FrameName>' src='*<FrameSrc file>' />` per `FramePath` level (`FRAME` for a `FRAME` level) | — | `FrameSrc` may be a full URL in one capture and a file name in another (`http://<host>/<page>.html` vs `<page>.html`) — wildcard the host; the frame's `id` / `name` must be confirmed live (`frame-unresolved`) |
| `HTML HasFrame` = `false` | no frame tag | — | |
| `HTML TagIndex` | `idx` | low | Position among same-tag elements |
| `innerHTML`, `outerHTML` | none | — | Content; a `class` or `id` inside may be recovered into `class` / `id` |
| `Path` (element children from `body`, § Format-wide conventions) | when no selector can be built from the capture's other criteria, a positional `DOMXPath` included: one `css-selector` from `body`, each segment `k` as `>:nth-child(k)` and `-k` as `>:nth-last-child(k)`, with the `HTML Tag` as `tag`, so a path that ends on another node matches nothing — `-1\|2\|1` → `<webctrl tag='DIV' css-selector='body>:nth-last-child(1)>:nth-child(2)>:nth-child(1)' />` | low | Position, flagged (§ Format-wide conventions) |

Sign-in pages (Microsoft 365 `login.microsoftonline.com`, a corporate identity provider such as PingFederate at `auth.<tenant>/idp/…`) are third-party applications: one Target Applications row each, one `<html>` scope per host, and the whole login is an **interactive OAuth priming** step. A mailbox connection in an interactive-token mode opens the same sign-in pages whenever no token is cached, and an unattended robot has to complete them itself, so the page targets are kept for that sign-in unless the connection authenticates without a user (an Integration Service connection, an app-only mode the tenant allows — source guide § Target Resolution 3).

## Active Accessibility (Win32 dialogs) → `wnd` + `ctrl`

Criteria observed: `Name`, `Role`, `Class`, `Path`.

| Criterion | UiPath | Confidence | Notes |

## SAP GUI (scripting interface) → `wnd` + `sap`

Source side verified on a native export driving SAP S/4HANA (transactions BP and FB75) in which the bots reach SAP two ways: a few recorder captures and, for everything else, a **scripting wrapper library** — one MetaBot logic per verb that takes the element's scripting id as an argument (source guide § Component Detection). UiPath side shape-verified on a comparable instance (SAP GUI for Windows 7.70, an S/4HANA system, the same transactions): the driver's default definitions, its selector evaluator and its attribute listings for session windows, modal dialogs, fields, buttons, tabs, combo boxes, a step-loop table and an ALV grid. Rows marked *(unconfirmed)* were exercised by neither.

Capture format: `technologyType: SAP`, `controlType` `TEXTBOX` / `BUTTON` / `CHECKBOX` (others by analogy); the action attribute is named after the control type as for every technology. The criteria sheet holds some thirty to fifty SAP scripting properties (`Name`, `Text`, `Tooltip`, `DefaultTooltip`, `Type`, `TypeAsNumber`, `Changeable`, `LeftLabel`, `RightLabel`, `Parent`, `ParentFrame`, `SessionId`, `ConnectionId`, screen and character geometry, …) of which **exactly two are enabled: `Role` and `Object Id`**. `Object Id` is the full scripting id **including its window segment** (`wnd[0]/usr/tabsTS/tabpMAIN/ssubPAGE:SAPLFDCB:0510/chkINVFO-XMWST`, `wnd[1]/tbar[0]/btn[12]`); `Role` is the SAP component type (`GuiButton`, `GuiCTextField`, `GuiCheckBox`, …) and the disabled `Type` criterion carries the same value. **The blob of a SAP capture holds only the capture point and the recorder version** (no object node, no path, no name), so the disabled criteria are the only description source: `Name` is the technical field name or button position (`INVFO-XMWST`, `btn[12]`), `Tooltip` / `DefaultTooltip` the caption a user sees (`Weiter   (F12)`, `Lieferdatum`), `Text` a check box's label (`Steuer rechnen`). The window of a `wnd[0]` capture is the session window (`SAP_FRONTEND_SESSION` of `saplogon.exe`); a `wnd[1]`+ capture sits in a modal whose WINDOW variable is a `#32770` window of `saplogon.exe` with the dialog's caption as title.

## AISense (computer vision) → window + image / Computer Vision target

An AISense capture locates a control by computer vision on a picture of the application window, not through the application's own object model (vendor documentation). Its blob holds no object tree: `targets` lists what the model recognised as the control's `vision` record — `mapping.control` with the control's `type`, the text it shows (`value`), its `bounding_box` on the capture machine's screen and the model's `score` — and the anchors it was linked to. An anchor is nearby text the bot finds more reliably than the control itself; a passive control (a field with no text of its own) is located through a static anchor text, a duplicated active text takes its first occurrence, and the `Anchor` criterion may hold a string variable (vendor documentation).

## Keystroke tokens

Source key syntax → the key names the genome states (execution encodes them in the owning skill's key syntax): `[ENTER]` and `[RETURN]` Enter; `[TAB]` Tab; `[F4]`…`[F11]` function keys; `[DOWN-ARROW]` / `[UP-ARROW]` / `[LEFT-ARROW]` / `[RIGHT-ARROW]` arrows; `[PAGE-DOWN]` / `[PAGE-UP]`; `[CTRL DOWN]x[CTRL UP]` Ctrl+x; `[ALT DOWN]x[ALT UP]` Alt+x; `[WIN DOWN]r[WIN UP]` Win+R; plain characters are typed. A `Keystrokes` command addresses a **window**; the control that receives the keys is the one the previous capture clicked or typed into (the skill's composite-interaction patterns, its keystrokes row). A command whose window is the focused-window preset (`windowValue=win(<CURRENTLY_ACTIVE>)`) or empty (`win("")`) sends to whatever window is in front — typically a browser's downloads flyout or prompt the preceding click opened; the keys then go to that element with the window left as it is, never after a bring-to-front of another window. The per-key `delay` (milliseconds) is kept as the keystroke activity's delay between keys.

## Pitfalls

1. **Enabled criteria are the only ones the bot matched on.** A capture with `Name` recorded but disabled and `Path` enabled ran positionally. The rebuild matches that `Name` instead (§ Format-wide conventions): it finds the control wherever the canvas puts it, where the path finds whatever sits at that position; the live pass confirms the name is unique in its frame.
2. **`Path` first segments disagree between twins of one control** (`-1|1|2|…` from the Enterprise 11 recorder, `1|1|2|…` from the source platform's current one). Neither is identity.
3. **Grid rows are same-named text fields.** `Name="Status"` with `Index=$var$` is not one control; it is the Status column. A UiPath target for "the Status cell of the current row" is a table pattern, not `idx`.
4. **Forms button names carry the mnemonic** (`OK ALT O`). The visible caption is `OK`; the accessible name is what the recorder saw. Match the recorded name; do not shorten it without a live check.
5. **Java dialogs are not Java.** The `Security Warning` shown by the Java runtime is a Win32 dialog (`#32770`) recorded with MSAA in some bots and a `SunAwtDialog` recorded with Java Access Bridge in others — two different windows in two technologies for the same user-visible prompt. Check both shapes live; scope each by its own class.
6. **Window titles change with the launcher.** The same applet frame is `<App>*` under `jp2launcher.exe` in one bot and `java.exe` in another, the login frame carries a different title and a desktop launch a third; a title-only window variable (`path` empty) says nothing about the executable.
7. **WINDOW variables named `window-N-1-1-1-1` are migration-generated**; the suffix encodes the nesting of the v11 command, not an identity. Several variables with identical title / class / executable in one bot are one window.
8. **HTML captures of the launch page were made in three browsers** (IE `IEFrame`, Edge tab titles with and without ` - Microsoft Edge`). One page, one scope on `url`; the browser is a Configuration Question.
9. **A `LABEL` control type on the launch button** (`HTML Tag` `B` inside `div#<button id>/span/b`) is the caption leaf; the click belongs on the enclosing clickable element — take the tag from the live DOM (the skill's rule that one tag is one node).
10. **Credential dialogs and identity-provider pages are login plumbing, not business steps.** They are carried as the targets of the one token sign-in the rebuild runs (§ HTML, sign-in pages); drop them only when the mail connection needs no interactive user.
11. **Native captures are position-first.** The source platform's recorder enables `Path` (and `Top`) by default and `Name` only when the author ticked it, so in a native export a large share of the enabled controls has no name at all. A disabled `Name` in the sheet names the field and identifies it (pitfall 1); where the sheet has none, the log line beside the capture names the field for the description, and live capture owes the identity.
12. **One control, two paths.** A Java application may rebuild its canvas per tab and version (Oracle Forms does), so the same field was captured at `…|2|1|1|198` and `…|1|1|1|198`, the same button at index `323` and `322` / `326` and `325`; the bots try one and fall back to the other. That is one element whose varying path segment is not identity — match on the label and let the driver resolve it.
13. **Grid columns are base offsets, rows are counters.** A native grid walk assigns `<base> + row` to one path tail per column (status, date, time) or increments several column indexes together; the offsets are the column identity in that screen build. The table pattern replaces them with the column header; the counter with the row rule.
14. **A record indicator is the row count.** `Record: 1/5` in an Oracle Forms status bar is the only place the bots learn how many rows a query returned; `Record: 1/?` means the query has not fetched everything, and the bots press last-record / first-record to force it. Read it as a status text, never as a control to click.
15. **A recorded title can carry invisible characters.** A browser tab title recorded as `<App> - [InPrivate] - Microsoft​ Edge` held a zero-width space before "Edge"; a title copied from the recorder into a selector carries it and never matches a live window whose title has none. Wildcard the title's tail and inspect recorded titles for non-printing characters before keeping them.
16. **A generic element under the window matches the first node of its role.** `<java role='label' />`, `<java role='panel' />` or `<java role='push button' idx='n' />` placed directly under the `<wnd>` resolves to whatever comes first in the tree (a frame caption, the main toolbar), not the recorded control. Every Java element without a unique `name` carries its screen's `internal frame` (and, for a toolbar button, the `tool bar`) as ancestors (§ Java, `Parent` and `Index` rows).
17. **The launch-failure page is a window.** A browser window titled `*Can't reach this page*` used as a launch-failure detector, with a read of the page's main heading, is the browser's error page: the read is the error message, the target is the browser, never an application row.
